# MiniRust Frontend Design

Visual quality guidance for `apps/web`. This skill assumes the constraints of
`minirust-web-ui` are already satisfied: Leptos SSR, Tailwind only, responsive,
accessible. Aesthetics never override those.

## Choose a direction before writing markup

Write down the direction in one sentence, then hold it for the whole page.

| Direction | Signals |
|---|---|
| Engineering precision | Monospace accents, hairline borders, dense technical detail, restrained accent |
| Editorial | Large display type, generous measure, asymmetric columns, minimal chrome |
| Dark luxury | Deep canvas, low-contrast texture, small bright accents, heavy whitespace |
| Utilitarian console | Tabular density, status colours, no decoration, keyboard-first |

The app's existing surfaces lean **engineering precision on a dark canvas**:
`slate-950` ground, `cyan-300` accent, `white/10` hairlines, monospace for
technical labels. A new page should extend that direction or deliberately depart
from it — not drift into an unrelated one.

## The quality bar

Eight checks. See `references/10k-checklist.md` for the full version.

1. **Point of view** — the page commits to a direction instead of assembling defaults.
2. **Typography does work** — scale and weight carry hierarchy; headings look chosen.
3. **Restrained colour** — one dominant tone plus sharp accents, not a rainbow.
4. **Hierarchy breathes** — a clear primary, then supporting layers, with real whitespace.
5. **Imagery with intent** — no generic stock-photo filler; empty states are designed.
6. **Motion whispers** — motion confirms an action or reveals structure, and never blocks it.
7. **Detail density is deliberate** — either restrained precision or controlled richness.
8. **It could not have been generated by default** — nothing is there for no reason.

## Typography

- Hierarchy from scale + weight + spacing, not from colour alone.
- Display headings: `font-black tracking-tight text-4xl sm:text-5xl lg:text-6xl`.
- Eyebrow labels: `text-sm font-bold uppercase tracking-widest text-cyan-300`.
- Technical and numeric labels: monospace (`font-mono`) for alignment and tone.
- Body measure stays readable: `max-w-prose` or `max-w-3xl` — never full-bleed text
  in a wide container.
- Do not introduce a web font without a concrete reason; it adds a network
  dependency and a layout-shift risk.

## Colour

- The canvas is dark; depth comes from translucency and hairlines, not shadows alone.
- One accent hue. A second accent is a decision to justify, not a default.
- Gradients are atmosphere, used sparingly and radially behind a hero — not as
  the fill for every panel.
- Text contrast is checked against the dark canvas for body copy, not only headings.

## Space and composition

- Prefer asymmetry and a clear focal column over evenly divided grids.
- Overlap and layering (`-z-10` atmosphere behind content) create depth that flat
  stacks cannot.
- Generous whitespace around the primary action; tighter grouping inside cards.
- Break the grid deliberately — an offset panel, a full-bleed section, a wider
  hero — rather than by accident.

## Motion

- CSS transitions only; this project does not ship a JS animation library.
- Keep durations short (`transition`, `duration-200`).
- Animate on state change (hover, focus, reveal), never on a timer that fights the user.
- Respect `prefers-reduced-motion`.
- No entrance choreography on an admin page. Motion belongs on landing surfaces.

## Anti-patterns

- Purple or blue gradient on a white background as a default hero.
- Identical cards in an even grid with no focal point.
- Emoji used as an icon system with inconsistent weight and meaning.
- Every element the same visual weight, so nothing leads.
- Decoration that carries no information.
- A card inside a card inside a card.

## Finishing

- Verify at 375 / 768 / 1280.
- Confirm the primary action is obvious within one second of looking.
- Confirm keyboard focus is visible on every interactive element.
- Run `minirust-ux-review` before declaring the page finished.
